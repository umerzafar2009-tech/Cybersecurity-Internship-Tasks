# Task 4: Network Intrusion Detection System (IDS)

## 📌 Project Overview
This project implements a network-based Intrusion Detection System using **Suricata**, configured with both community-maintained and custom detection rules. The system monitors live network traffic in real-time, generates alerts for suspicious activity, triggers automated response actions, and visualizes the results through charts — simulating a real-world SOC (Security Operations Center) workflow.

## 🎯 Objectives
- Set up a network-based IDS using Suricata
- Configure detection rules and alerting
- Continuously monitor live network traffic for threats
- Implement automated response mechanisms for detected intrusions
- Visualize detected attacks using charts/graphs

## 🛠️ Tools & Technologies Used
- **Suricata 8.0.7** — Open-source IDS/IPS engine
- **Emerging Threats Open Ruleset** — 53,000+ community detection rules
- **Python 3** — For response automation and visualization
- **Matplotlib** — For generating alert charts
- **Kali Linux** — Operating environment

## ▶️ How to Reproduce This Setup

### 1. Install Suricata
sudo apt update && sudo apt install suricata -y

### 2. Download detection rules
sudo suricata-update

### 3. Add custom rules
sudo cp custom.rules /etc/suricata/rules/custom.rules
sudo cp custom.rules /var/lib/suricata/rules/custom.rules

### 4. Test the configuration
sudo suricata -T -c /etc/suricata/suricata.yaml -v

### 5. Run Suricata in live mode
sudo suricata -c /etc/suricata/suricata.yaml -i eth0

### 6. Run the response monitor (in a separate terminal)
sudo python3 response_monitor.py

### 7. Generate visual charts
sudo python3 visualize_alerts.py

## 📊 Sample Detection (Live Test)
A `ping google.com` command was run to generate ICMP traffic. Suricata detected it instantly with signature "ICMP Ping Detected - Possible Network Scan". The response monitor then automatically logged the incident and added the source IP to the watchlist — all within the same second.

## 🔍 Key Learnings
- An IDS passively monitors and alerts on suspicious traffic, unlike an IPS (Intrusion Prevention System) which can actively block it.
- Signature-based detection works by matching traffic patterns against a database of known threat signatures (rules).
- Rules follow a structured syntax: action, protocol, source/destination, and rule options (message, signature ID, etc.).
- Real-world SOC teams rely on layered rule sets — community-maintained rules (like Emerging Threats) combined with custom rules tailored to the organization's environment.
- Automated response (logging, flagging, and in production, automatic blocking) is critical for reducing MTTR (Mean Time to Respond).
- Visualizing alert data helps identify patterns (e.g., repeated attacks from a single IP) that may not be obvious from raw logs alone.
